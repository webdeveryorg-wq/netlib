# План обновления netlib — карточка 69212489

Plan ID: `kaiten-69212489-netlib-update`. **Версия 3 утверждена пользователем 2 сентября 2026 года.**

Основной подробный план теперь находится в OpenSpec:

- [Утверждённое предложение](../openspec/changes/update-netlib-stability/proposal.md).
- [Контракт, сценарии SC-01–SC-09, критерии AC-01–AC-09 и матрица проверок](../openspec/changes/update-netlib-stability/design.md).
- [Этапы и состояние выполнения](../openspec/changes/update-netlib-stability/tasks.md).

Принятое решение: **наш серверный форк + оригинальный клиент `@poki/netlib@0.0.20`**. Сначала выборочно переносим серверные #340, #344, #388 и серверную часть #364; после проверок сервер обновляет пользователь по подготовленным командам. При следующем выпуске шахмат обновляем оригинальную зависимость с 0.0.16 до 0.0.20 и lock-файл.

Состояние реализации: серверные изменения опубликованы коммитом a8e1ea1; preflight и резервная копия подтверждены. См. [результаты](69212489-server-validation.md) и [регламент обновления](69212489-server-update-runbook.md). Игровая проверка выявила существующее ограничение рестарта при подключении и активной партии — требуется окно обслуживания. Клиентский выпуск пока заблокирован SC-05: оригинальный 0.0.20 создаёт Peer из очереди после закрытия Network. Утверждённый v3 требует отдельного пересмотра клиентского объёма при таком дефекте. Новый серверный образ на production ещё не применялся, шахматная зависимость не изменялась.

Публикация клиентского форка для шахмат, миграции latency и обновление Go/зависимостей в этот этап не входят. Совместимость, реальный WebRTC, восстановление и откат должны пройти проверки до выпуска. Окно обновления сервера определяется после репетиции на активной партии.

Этот указатель заменяет предыдущий неутверждённый план, предполагавший клиентский тег нашего форка. [Исходный анализ истории](69212489-netlib-upstream-review.md) сохраняется как материал исследования.

# Ручное обновление сервера netlib

Карточка 69212489, план v3. Серверный коммит: `a8e1ea165c8d1fe059fd15fea97504d4f89dbad3`, ветка `codex/69212489-netlib-update`. Команды на production выполняет пользователь.

## Подготовка

Перед обновлением сверить рабочий SHA, чистоту checkout, Compose project и файлы, действующие переменные контейнера, опубликованные порты, активную БД и её схему. Секреты в вывод не включать. Отдельно проверить фактический маршрут прокси и адрес сигналинга в игре.

Сохранить текущий образ под уникальным rollback-тегом и в архив, дамп активной БД, настройки контейнера/Compose и сертификаты с конфигурацией действующего прокси. Копии с секретами хранить в закрытом каталоге вне контейнеров. Проверить читаемость дампа, архивов и контрольные суммы. Чтение дампа через `pg_restore --file=/dev/null` не является пробным восстановлением в новую БД.

Для текущего развёртывания пользователь подтвердил совпадение настроек и успешное резервное копирование. Точные пути, имена копий и ID образов находятся в частной инструкции и не публикуются в репозитории.

## Сборка и применение

Получить проверенный коммит и собрать образ, пока старый контейнер продолжает работать. Использовать прежний Compose project и тот же набор файлов конфигурации. В каталоге проекта при отсутствии дополнительных override:

```sh
docker compose build netlib
```

При ошибке сборки остановиться. До применения определить окно обновления по результатам проверки реальной игры. Один экземпляр сигналинга не обеспечивает обновление без разрыва WebSocket.

```sh
docker compose up -d --no-deps --no-build netlib
```

В проверенном развёртывании хостовый Nginx проксирует на опубликованный порт `localhost:8080`. При сохранении этого порта его reload не требуется. Остановленный контейнер Docker-Nginx не участвует в выпуске. БД и certbot не пересоздаются.

В другом развёртывании, где Nginx использует Docker-имя `netlib`, после смены адреса контейнера требуется проверить upstream и при необходимости выполнить `nginx -t` и reload. Локальная репетиция использовала именно такой тестовый прокси.

## Проверка и откат

Проверить образ и состояние контейнера, `/health`, `/ready`, затем реальный публичный WebSocket: создание/поиск/вход в лобби, обмен и партию действующей сборки. Одного HTTP 200 недостаточно.

При регрессии применить прежний неизменяемый образ только к сервису netlib. Для этого использовать последний Compose override с `services.netlib.image`, содержащим сохранённый rollback-тег, и `up -d --no-deps --no-build netlib`. Сохранить project, порты, остальные параметры и тома; повторить сетевые проверки. Схема БД в этом изменении не меняется.

Обычное обслуживание не использует `down -v`. `server:restart` перезапускает текущий контейнер, `server:build` собирает, `server:update` применяет уже собранный образ. `server:start` предназначен для первоначального запуска всего состава.

Клиентский выпуск оригинального `0.0.20` остаётся отдельным этапом: найденный SC-05 требует пересмотра клиентского объёма до изменения зависимости. Текущие шахматы сохраняют `0.0.16`.
